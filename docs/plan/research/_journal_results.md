## R2-emhass.md

**Summary.** EMHASS (davidusb-geek/emhass, MIT, v0.18.8, commit 4efdaa2 of 2026-11-05) was shallow-cloned and its optimiser, forecasters, MPC entry point, price plumbing and web UI were read with line references; nothing was executed. The optimiser is a CVXPY MILP solved by HiGHS (migrated from PuLP in release 0.16.0, 2026-01-21), built once with cp.Parameter inputs and re-solved with warm start under a structural cache key; charge/discharge and import/export exclusivity are enforced with per-step binaries, the SoC is a cumulative-sum expression in Wh, the terminal SoC is a soft equality priced at 100 times the dearest tariff, and a convex PWL "stress cost" plus per-kWh throughput weights are the only wear terms. Demand charges are modelled as an epigraph over a window mask with an incumbent floor and interval averaging, which maps directly onto a Pakistani MDI; the deferrable-load block supplies start/stop binaries and minimum on/off windows that the EMS can reuse for a genset. perform_naive_mpc_optim is a thin receding-horizon slice (prediction_horizon steps, soc_init from the caller, soft soc_final, out-of-band SoC recovery) with no state carried between ticks beyond what the caller passes; prices arrive as two per-step currency/kWh arrays and EMHASS is explicitly tariff-agnostic. The load forecaster is skforecast ForecasterRecursive around a scikit-learn model with lags plus calendar features (documented R2 0.27 in its own example); the valuable forecast pieces are the persistence baseline, the walk-forward calibration report, the pvlib prior with learned correction, and an adaptive-conformal self-tuning of the P10/P50 blend. The web UI is server-rendered Plotly fragments in a Jinja template plus a versioned JSON plan endpoint; nothing there is worth copying as code. EMHASS has no genset, no outage or reserve model, no ICP block tariff, no net-metering period netting, no inverter TOU-slot delivery, no savings verification and no multi-tenancy, so the recommendation is to lift patterns and a dozen small MIT functions rather than fork the 9,295-line optimization.py. Notes are at C:/Users/SaadTahir/Videos/solarytics/plan-work/research/R2-emhass.md (322 lines, 11 sections).

- SoC dynamics (3548-3556): power_flow = p_sto_pos/eff_dis + p_sto_neg*eff_chg, energy_change = power_flow*time_step, stored = soc_init*cap - cumsum(energy_change) in Wh; the terminal SoC is a soft equality with slacks (3643-3649) priced at 0.001*100*max(load_cost) per Wh (7760-7765, constant SOC_FINAL_DEVIATION_PENALTY_FACTOR = 100 at line 94).
- battery_stress_cost (2049-2082, 3664-3676): a quadratic y = max_cost_step*(x/max_power)^2 sampled into 10 chords (battery_stress_segments default 10) and added as a convex epigraph stress >= +-slope*P + intercept on P = p_sto_pos - p_sto_neg; no binaries, unit is currency per kWh at full load; default 0.
- Demand charge (2783-2830, 2302-2414, 3124-3142): peak_import >= window_mask[t]*p_grid_pos[t] or interval-average matrix form with capacity_charge_interval_timesteps native steps per tariff interval, floored at current_period_peak (W), priced at capacity_cost_per_kw*peak/1000 unscaled by time; runtime inputs are caller-owned (docs/passing_data.md 327-410).
- Deferrable-load unit-commitment patterns reusable for a genset (6562-6684): start[t] >= bin2[t]-bin2[t-1] and start[t]+bin2[t-1] <= 1; max starts sum(start) <= K; min on time sum(bin2[t:t+N]) >= (window_end-t)*start[t]; min off time via a stop binary pinned by three inequalities; semi-continuous p == nominal*on (6753-6754).
- Time-varying grid limits: maximum_power_from_grid and maximum_power_to_grid accept per-step arrays via _prepare_power_limit_array (1987-2021); setting both to 0 in a window is the only existing hook for an outage, and no code does it.
- Naive MPC (9023-9240, command_line.py 3067-3210): rejects prediction_horizon < 5, slices inputs with .iloc[:prediction_horizon], takes soc_init/soc_final as runtime fractions (fallback chain init <- final <- battery_target_state_of_charge, 7523-7534), handles a measured SoC outside [soc_min, soc_max] with single-recovery-transition constraints (3597-3634, gaps set at 7842-7853), carries no state between ticks; plan persisted to plan_latest.json and served by GET /api/v1/plan (plan_store.py 35-53, web_server.py 842).

**Recommendations.**
- Do not fork optimization.py; write OnyxLeaf's own optimiser module (roughly 600-900 lines) on CVXPY plus HiGHS using EMHASS's define-once cp.Parameter structure, DPP-safe expressions, a structural cache key per site, warm start, and a per-site lock; add cvxpy and highspy to the backend requirements and put a 192-step benchmark gate before pilot.
- Copy, with the MIT notice in a THIRD_PARTY_NOTICES.md and a file header, only the small self-contained pieces listed in section 8.2 of the notes: _build_stress_segments and _add_stress_constraints, _prepare_power_limit_array, _has_feasible_incumbent and _needs_relaxed_retry, the min-on/min-off block, get_naive_load_forecast, get_lags_list_from_frequency, compute_forecast_metrics, add_date_features, pv_bias_calibration.py, the forecast_calibration walk-forward skeleton, and plan_store.py.
- Adopt EMHASS's sign and unit conventions (W per step, Wh SoC as a cumsum expression, prices in currency/kWh, scale 0.001*time_step), its 'never infeasible' policy (soft terminal SoC priced above the dearest tariff, out-of-band SoC recovery, accept time-limited incumbents, one relaxed retry, never republish after an exception), and its versioned plan schema with last-run and plan endpoints.
- Model the genset by generalising the deferrable-load block: on, start and stop binaries with the three-inequality edge pinning, minimum on/off windows, a start cost, p_min*on <= p_gen <= p_max*on, fuel cost fuel_price*(a*on + b*p_gen)*time_step, and on[t] <= 1 - grid_available[t] where the ATS forbids parallel operation.
- Model outages with a per-step grid_available parameter that zeroes the import and export limits (EMHASS's per-step limit arrays already support this), a per-step reserve floor on stored energy derived from the outage-probability forecast (EMHASS's soc_target_floor pattern), and a priced shortfall slack.
- Model the MDI charge exactly as EMHASS's demand-charge epigraph (window mask, interval averaging with capacity_charge_interval_timesteps = 2 at 15-minute steps for a 30-minute average, incumbent floor, consideration mask), with the tariff engine owning the billing-period incumbent and its reset date.
- Add what EMHASS lacks in the tariff model: ICP block pricing on cumulative monthly import (needs a binary or an a-priori exceedance decision and a month-to-date parameter), and legacy net-metering period netting; net billing is already EMHASS's 'profit' objective with asymmetric per-step prices.
- Add a Mode A post-processor that fits the 96-step daily plan into the K charge/discharge slots an inverter accepts, and a per-brand executor; EMHASS has nothing for this.
- Build the forecasting stack as pvlib prior plus a per-site xgboost correction and quantile model with calendar, Pakistani holiday, day-type, grid-availability and weather features, keep persistence as the baseline, run EMHASS-style walk-forward calibration per site, and run the ACI self-tuning of the conservative PV blend nightly.
- Use perform_perfect_forecast_optim's idea (hindsight re-solve on realised data) as the perfect-information upper bound in the savings report, but build the 1-minute counterfactual replay, switchback A/B and bill rebuild from scratch since EMHASS has none.
- For the frontend take only ideas from the EMHASS UI: step-shaped power lines, a SoC panel with the band, a tariff staircase under the plan, an optim_status badge, a records table, and an OpenAPI contract for the plan JSON.

## R1-evcc-optimizer.md

**Summary.** evcc-io/optimizer (MIT, "Copyright (c) 2025 andig", 99 stars, 24 forks, last push 2026-11-04, no releases, 12 contributors) is a 1,456-line PuLP 4 MILP wrapped in a Flask/flask-restx service, maximising import cost, export revenue and terminal stored-energy value, with soft SoC bands, charge goals, charge demands and grid limits implemented as unbounded slack variables priced at tiered multiples (x1000, x100) of a per-request penalty base, which is why it never returns infeasible on consistent input. It takes per-step dt in seconds (the evcc client sends 15-minute slots for 48 hours then hourly; stored cases run 4 to 245 steps), runs CBC 2.10.10 by default or HiGHS 1.15.1 in process, under a 10 s wall clock split over a probe, cost, tie-break and continuity stage ladder that accounts for about 600 of the file's lines and exists for EV tie-breaks on a home-EMS latency budget. Measured in its own source: joint-path p95 about 1.5 s, splits 5.4 s each, 97 percent of traffic proven in one solve, about 250 steps with two batteries as the practical ceiling. Of the target engine's elements, the balance, SoC dynamics, direction gate, soft-band, asymmetric prices and terminal value lift as is; the demand-rate block (rate times horizon peak above a threshold) maps directly onto the MDI charge by setting the threshold to the peak-to-date; genset unit commitment, outage availability, unserved-load slack, reserve SoC, ICP baseline pricing and PWL wear are new, and the penalty-tier scheme is the part most likely to misbehave once Rs 1,250/kW MDI and Rs 400/L diesel coefficients enter it. A prototype of the full target model written for this note on scipy.optimize.milp (HiGHS, already in the ops env) solves 192 steps with 768 binaries to proven optimality in 8 to 10 s on one core; the genset binaries cost 1 to 5 s, the ICP baseline-exhausted chain 5 to 7 s, and evcc's direction and lock binaries are redundant at net-billing prices. Recommendation: re-implement with evcc's structure on highspy (start on scipy.milp), porting a named list of constructions with an MIT notice, and do not fork: the fork drags in Python 3.13, pulp 4 and CBC, keeps EV dead weight and CBC workarounds, and its effort (15 to 18 days) is not lower than a clean build (10 to 14 days).

The notes file writes out, in plain math with file and line references, the generator fuel curve (two-point slope/intercept from full- and half-load HHV efficiencies), the on/off and minimum-turndown big-M pair, the hourly O&M linearisation, the deterministic single-outage step-set handling, the stochastic multiple-outage block (start steps x durations x probabilities, minimax over start, expectation over duration, VoLL-priced unserved load, per-outage fuel tank, optional minimum SOC in outage), the battery dispatch constraints the outage block relies on, the daily SOH degradation recursion with augmentation and replacement costing, the tariff and demand-charge constraints (monthly and TOU peaks, MPC previous-peak lower bounds, lookback, tiers, export bins, the no-simultaneous-import/export binary), and the MPC module's build order, objective and inputs. Three defects were found by reading: the fuel intercept is derived per kW rated but never multiplied by the generator size in the generator constraints; the MPC path prices fuel in $/gallon per kWh of fuel (a 40.7x units error); and the MPC's stochastic-outage code path references undeclared variables and a misspelled function, so outage-aware MPC does not run in v1.0.1. REopt has no minimum up/down times, start costs or ramp limits for the generator, no receding-horizon loop (run_mpc solves one horizon; the caller must carry SOC, month-to-date peaks, tank and genset state), and its degradation defaults are NMC (Kokam 75Ah), not LFP. HiGHS is not an indicator-compatible solver in REopt, so the big-M branches documented are the ones that actually run. The Apache-2.0 obligations (sections 4(a)-(d), 6) and the REopt trademark facts (USPTO reg. 6022044, class 42, owner Alliance for Energy Innovation, LLC per an aggregator; NREL renamed National Laboratory of the Rockies on 1 Dec 2025) are recorded with what is verified and what is not. A scipy.optimize.milp toy port of the genset block solved correctly over HiGHS and the fuel-curve arithmetic was re-computed in Python, with litres-per-hour values for a 100 kW set.

**Key findings.**
- Fuel curve: src/core/utils.jl lines 652-665 derive slope a = (1/eff_full - 0.5/eff_half)/0.5 [kWh fuel per kWh_e] and intercept b = 1/eff_full - a [kWh fuel per hour PER kW RATED]; defaults eff_full = eff_half = 0.322 (generator.jl 111-112; MPC 0.3233, structs.jl 302) give b = 0, i.e. a flat 0.0763 gal/kWh (0.289 L/kWh). With 0.34/0.30 a 100 kW set idles at 3.65 L/h and burns 0.274 L/kWh at full load (appendix A).
- Intercept scaling omission: generator_constraints.jl line 11 and outage_constraints.jl lines 181-182 multiply the per-kW intercept by the on-binary only, never by dvSize/S; the CHP path scales it via a linearised dvMGCHPOnSize = size * binary (outage_constraints.jl 237-249). Port as F[t] = a*h*P_gen[t] + b*S*h*u[t].
- MPC fuel-cost units bug: src/mpc/model.jl lines 169-171 overwrite TotalGenFuelCosts with sum(dvFuelUsage * fuel_cost_per_gallon) although dvFuelUsage is in kWh of fuel (model.jl 270 comment; results/generator.jl 60 divides by HHV to get gallons), overstating fuel cost by HHV = 40.7. Do not use run_mpc with a generator as the WP6 reference case.
- On/off and turndown (generator_constraints.jl 20-37): P <= S_max*u and f_min*S - P <= S_max*(1-u); for an on-grid analysis the turndown applies only in time_steps_with_grid (comment line 25), i.e. NOT during a deterministic outage; inside stochastic outages it IS enforced (outage_constraints.jl 289-294). MPC default min_turn_down_fraction = 0.0 with a TODO (structs.jl 306); only_runs_during_grid_outage defaults true (structs.jl 307), which fixes P_gen = 0 whenever the grid is up (generator_constraints.jl 40-44).
- No minimum up time, minimum down time, start/stop binaries, start cost or ramp limit exist for Generator anywhere in src/constraints, src/core/generator.jl or src/mpc (grep); the only ramp constraint is for CHP (chp_constraints.jl 196-209). The standard UC formulation to add is written in section 2.6 and was exercised in the toy MILP.
- Deterministic outage: time_steps_without_grid = [start..end] inclusive, 1-based (reopt_inputs.jl 1227-1247; electric_utility.jl 59-63); in those steps grid import, grid-to-storage and exports are fixed to 0 (reopt.jl 192-210; mpc/model.jl 81-96), the load balance switches to critical_loads_kw (load_balance.jl 46-53), and the storage SOC recursion drops the grid term (storage_constraints.jl 94-99). This path works in the MPC and is the pattern for scheduled load-shedding windows.
- Stochastic outages (electric_utility.jl 165-174): outage_start_time_steps (set TZ), outage_durations in time steps (scenarios S), outage_probabilities (default uniform, must sum to 1); unserved load U[s,tz,ts] = L_crit - (MG production - MG charge - MG curtail) - MG discharge (outage_constraints.jl 41-48); Cost_max[s] >= pwf_e * sum VoLL*U over the duration for every start tz (61-63), ExpectedOutageCost = sum prob[s]*Cost_max[s] (65-67); min_resil_time_steps forces U <= 0 for the first k steps (52-58); MG battery starts from Emg[s,tz,0] <= E[tz] (321-323) with optional soc_min_applies_during_outages (341-346, default false); one fuel tank per outage (186-188).
- MPC outages are non-functional in v1.0.1: build_mpc! (mpc/model.jl 180-207, with '# TODO: random outages in MPC?') calls add_MG_fuel_burn_constraints, which does not exist (the function is add_MG_Gen_fuel_burn_constraints, outage_constraints.jl 171), and the MPC add_variables! comments out dvMGsize, dvMGTechUpgradeCost, binMGTechUsed, binMGStorageUsed (mpc/model.jl 296-306) that add_outage_cost_constraints and add_MG_size_constraints reference; test/runtests.jl 467 says 'TODO test MPC with outages'.
- Demand charges: dvPeakDemandMonth[m] >= grid purchase at every step of the month (electric_utility_constraints.jl 261-264) and dvPeakDemandTOU[r] >= grid purchase in each ratchet's steps (297-300); MPC adds lower bounds from monthly_previous_peak_demands and tou_previous_peak_demands (mpc/constraints.jl 2-15), so the objective pays rate * max(previous peak, horizon peak) — the month-to-date MDI increment logic the EMS needs. Lookback in two forms (406-437), tiers via binaries (267-291), bill assembly at 511-518.
- Simultaneous import/export: binary binNoGridPurchases[t] with big-M = max load + thermal loads + storage max_kw (electric_utility_constraints.jl 353-364); created only when allow_simultaneous_export_import = false and export bins exist (reopt.jl 697-700; mpc/model.jl 275-279); electric_utility.jl line 7 advises it only when the export rate exceeds the energy cost. NEM export rate is -0.999 * energy_rate (structs.jl 175; electric_tariff.jl 161), and the NEM annual sell <= buy rule is skipped for MPC (electric_utility_constraints.jl 33-43).
- Battery degradation (battery_degradation.jl 103-113): SOH[1] = E_cap; SOH[d] = SOH[d-1] - h*(k_cal*alpha*Eavg[d-1]*d^(alpha-1) + sum_j k_cyc[j]*Eminus_sum[d-1,j]); defaults k_cal = 1.16e-3, k_cyc = [2.46e-5], alpha = 0.428, cycle_fade_fraction = [1.0] (electric_storage.jl 153-160), set to match an NMC-Gr Kokam 75Ah cell (CHANGELOG 223), not LFP; the docstring (electric_storage.jl 52-56) writes the calendar term with a hard-coded sqrt(d) while the code uses alpha*d^(alpha-1); augmentation cost = sum maintenance_cost_per_kwh[d-1]*(SOH[d-1]-SOH[d]) (210-220); replacement strategy uses monthly binaries with big-M 24*max load (155-208).

**Recommendations.**
- Port the mathematics, not the Julia: implement sections 2.3 (with the intercept multiplied by S), 2.4, 2.6, 4, 6.3, 6.4 and 8 of the notes in one Python optimiser module on scipy.optimize.milp/HiGHS (or PuLP for named constraints), keeping the REopt file:line references in docstrings for audit.
- Genset block v1 must add what REopt lacks: start/stop binaries, minimum up and down times, start cost, tank-litre limit, hours-run and on/off state carried between solves, and a fuel curve from measured full- and half-load litres per hour of the site's set (use the two-point method, in litres, not REopt's US-gallon defaults); enforce turndown in every step including outages.
- Outage handling v1: a per-step data flag g[t] (import, export and grid-charge bounded by g[t]*cap; load balance uses critical load when g[t] = 0) for announced load-shedding windows, plus a time-varying reserve-SOC floor driven by the outage-probability forecast; v2: the REopt scenario block (start steps x durations x probabilities, VoLL-priced unserved load, minimax or expectation over start) without the sizing variables, benchmarked for solve time in WP6.
- Demand (MDI/TOU): carry month-to-date and TOU-window-to-date peaks into every 15-minute solve as lower bounds on the peak variables (REopt's previous-peak pattern); decide per DISCO meter whether the peak is per-15-minute step or a 30-minute rolling mean (G[t]+G[t+1])/2; encode the sanctioned-load MDI floor as a constant lower bound.
- Export: one wholesale-style bin at the net-billing rate with net_metering_limit = 0 for net-billing customers (no binaries); a NEM bin plus an annual net-energy state carried by the EMS for legacy net-metering customers (REopt skips that rule in MPC); keep the no-simultaneous-import/export binary behind a flag, default off while export credit < import price.
- Wear: use a marginal cycle price c_cyc = replacement cost per kWh * k_cyc on discharged energy and a calendar term on held SOC derived from the SOH recursion (section 5.5), with LFP coefficients from BLAST-Lite, since REopt's defaults are NMC; report EFC as a metric; do not port the multi-year SOH recursion into the 48-hour MPC.
- Terminal condition: replace REopt's add_soc_incentive (default true) with an explicit terminal SOC value equal to the expected next-period peak price times eta_d, or a terminal SOC floor.
- WP6 reference case: build the REopt cross-check with the annual run_reopt at fixed sizes (min_kw = max_kw = existing) for a PV + battery + TOU + demand-charge case without a genset; cross-check the genset case against brute-force enumeration of a 1-day problem instead, because run_mpc has the fuel-cost units error and its outage path is broken.
- Licence hygiene in solarlytics-backend: a THIRD_PARTY_NOTICES.md line attributing the formulation to REopt.jl (NLR, Apache-2.0), a copy of the Apache-2.0 text and the REopt NOTICE text only if any code is translated line-for-line, modified-file markers in that case, never vendor the clone (it carries unreviewed SAM/SSC and solver binaries), and no 'REopt' in product names, UI strings, marketing or domains.
- Keep big-Ms tight (S for the genset, sanctioned load for the import/export binary, P_cap for any charge/discharge binary) so a 192-step MILP with a few hundred binaries stays inside the WP6 30-second budget; warm-start each solve from the previous plan shifted by one step.
