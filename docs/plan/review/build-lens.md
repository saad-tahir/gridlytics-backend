## A. Parts 0, 2 and 3: decisions, architecture, data model

### F1 (high). The role model contradicts itself and the tenancy model, and no permission is ever named

- **Location:** D4 (line 42); Part 10.5 (roles table); Part 9.4; Part 2.8 bullet 2 ("`auth.need(permission)` first"); PLT-03 ("the EMS roles and permissions"); R7 section 10.1 "Decisions inside the lift".
- **Claim:** D4: "roles admin, operator, analyst, viewer (Part 10)". 10.5: owner, admin, operator, analyst, viewer, installer, machine. 9.4: Owner, Operator, Analyst, Viewer (no admin).
- **Defect:** three role lists in one plan. 10.5's "installer (optional, a member of the installer company that owns the site)" cannot exist: a site lives in exactly one company's file and "A company's file holds nothing another company may read" (3.4, line 273), so a member of another company can never be shown that site. "admin: As owner except transferring ownership" names a feature no item builds. The plan never lists a permission name, although every route, every walk case and every `RoleGate` is keyed on one; R7 section 10.1 proposes eight names and the plan adopts none. The viewer "server-side field filter" (9.1) names no key list, so the walk test that "greps the answers for cost keys" (U2 2.4) has nothing to grep for.
- **Evidence:** lines 42, 185 to 187, 273; Part 10.5; Part 9.4 table; R7 section 10.1 bullet "Roles"; Solarlytics' membership roles are `owner|admin|member` in `platform.db` with app roles from `role_presets` (U2 1.4 "Tenancy"), so "owner" is a membership fact, not an app role.
- **Replacement (10.5, replacing the table):** "Membership roles in `platform.db` are the lifted `owner|admin|member`; the owner is the pinned administrator. App roles in the company file: `admin`, `operator`, `analyst`, `viewer`. Permissions: `manage_members`, `edit_money_settings`, `edit_sites`, `edit_tariffs`, `approve_tariff`, `override`, `apply_plan`, `change_tier`, `ack_alerts`, `upload_data`, `export`, `see_costs`, `see_fee`. admin: all; operator: edit_sites, override, apply_plan, ack_alerts, upload_data, see_costs; analyst: export, see_costs, see_fee, approve_tariff; viewer: none of these. A machine key carries scopes, not a role. The installer role is deferred: an installer is a member of the site's company as operator. The viewer filter strips every key matching `price|cost|fee|wear|_rs|rupee` from every answer, and `test_role_walk.py` greps for those keys." Then make D4 and 9.4 say the same four app roles.

### F2 (medium). Open mode and the default workspace file: the lifted tests need them, the plan never decides them

- **Location:** Part 2.7 Data row and Part 10.1 `data/` (no default workspace file); D4 ("no self sign-up"); Part 2.8 (no mention of open mode); Part 10.3 (`_DB` listed); Part 10.4 step 5 ("`test_auth.py`'s first five").
- **Claim:** the data folder holds `platform.db` and per-company files only; sign-in "as Solarlytics".
- **Defect:** Solarlytics' guard has an open mode: with no token, no account in `platform.db` and a local client, the request works on the default file (`api.py` 467 to 472, `auth.open_mode`, `auth.LOCAL_CLIENTS`). The carried tests depend on that default file: `conftest.py` sets `SOLARLYTICS_DB` to a temp file; `identities.py` registers each test company with `db_file = store.DB_PATH`; `test_auth.py` test 1 is "the workspace is open until the first account". The plan lists `_DB` as a setting but no default file in the data folder, and never says whether open mode is kept. The agent must either carry a sign-in bypass the plan never approved (anyone on localhost gets in before the first account) or drop it and watch the carried tests fail. Also, tests 4 and 5 of `test_auth.py` are Solarlytics role tests ("a sales user never sees a cost", "each role changes only its own settings") and cannot pass as carried.
- **Evidence:** `backend/solarlytics/api.py` 469 to 472 ("if not auth.open_mode() ... return _refusal(rid, 401, 'Sign in first')"); `backend/tests/conftest.py` line 8; `backend/tests/identities.py` docstring; `backend/tests/test_auth.py` tests at lines 50, 61, 70, 79, 97; U2 1.7 host contract row "platform.py: `store.DB_PATH`".
- **Replacement (10.4, new step 2b):** "Open mode is not lifted: `auth.open_mode()` returns False and the guard answers 401 to every request without a token or key. `GRIDLYTICS_DB` stays as the tests' default file path (the conftest and `identities.py` use it as each test company's `db_file`) but no route ever serves it. From `test_auth.py` carry tests 2 and 3 as they are, drop test 1, and re-aim 4 and 5 as 'a viewer never sees a fuel price or a fee' and 'each role changes only the settings its permissions allow'."

### F4 (medium). The forecast issue is timed after the tick that needs it
